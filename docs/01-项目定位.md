# 01 · 项目定位

## 解决的问题

计算机专业学生不知道大学各阶段该学什么、所学课程与就业市场有什么联系、有限时间该优先投入哪里。目标岗位或路径（就业/考研）变化时，已有规划难以快速调整。

## 面向用户

计算机方向本科生（大一大二为主），输入自己的年级、技术基础、每周可投入时间和目标岗位，得到分学期的成长路线图，并能通过对话动态调整。

## 五大核心功能（对齐老师要求）

| # | 功能 | 对应模块 |
|---|---|---|
| 1 | 从真实招聘信息提取技术栈、学历、项目经验、通用能力 | 流水线① 抽取 |
| 2 | 相近技能归并，识别高频核心要求、区分硬性/加分 | 流水线② 归并 |
| 3 | 岗位能力 ↔ 课程/竞赛/实习/项目机会映射 | 流水线③ 映射 |
| 4 | 按年级/基础/每周时间生成分学期成长路线图 | 流水线④ 规划 |
| 5 | 目标岗位或时间条件变化时自动重规划 | 对话 Agent ⑤ |

后续增强（已列入路线图，非首版必须）：接入 Exa MCP 搜索实时招聘资讯，缓解静态语料的数据滞后问题。

## 成功标准（对照老师评分表）

1. **现场演示一个完整任务**：输入画像 → 输出多学期路线图（流式可见过程）。
2. **演示一次条件改变后的调整**：就业 → 考研切换，方案自动重排。
3. **真实数据与证据**：每条 JD 保留来源链接，可核验；统计结论（如"数据库优化出现率 X%"）可复算。
4. **系统测试与动态改进**：至少 2 轮组内测试留痕（输入→问题→改动）。
5. 技术实现可讲清楚"Agent 如何感知、决策、调用工具、更新状态"。

## 明确不做（范围外）

- 不做用户注册/多用户系统（单机演示）
- 不做生产级爬虫（数据源接口已预留，语料手动收集）
- 不做向量库/RAG（语料结构化后直接进上下文）
- 不做云端部署（本地运行 + 录播兜底）
