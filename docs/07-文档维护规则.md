# 07 · 文档维护规则

## 文档地图与负责人

| 文档 | 性质 | Owner | 更新时机 |
|---|---|---|---|
| README.md | 门面 | 项目负责 | 结构/状态变化时 |
| 01-项目定位 | 稳定 | 项目负责 | 很少改；改需组会 |
| 02-架构设计 | 稳定 | 架构 Owner | 模块/契约/分层变化时（先 ADR） |
| 03-开发路线图 | 半稳定 | 项目负责 | 里程碑调整需组会 |
| 04-进度状态 | **高频** | 当值开发 | 每完成一任务/每合并；这是全组每天唯一必看的文档 |
| 05-环境与依赖 | 半稳定 | 环境维护者 | 装包/换版本/踩新坑时立即补"常见坑" |
| 06-开发规则手册 | 稳定 | 项目负责 | 新增规则时 |
| 07-本文档 | 稳定 | 项目负责 | 文档体系变化时 |
| decisions/*.md | 只增不改 | 决策提出人 | 新决策时新增文件 |
| research/*.md | **只读归档** | 无 | 不再维护，供追溯 |

## 核心规则

1. **代码与文档同一次提交**：改了架构/依赖/进度，对应文档在同一分支同一提交里更新，避免"代码到了文档没到"。
2. **ADR 只增不改**：推翻旧决策 = 新写一份 ADR 并在旧文件顶部加一行"已被 ADR-00XX 取代"。每份 ADR 固定结构：背景 / 备选 / 决定 / 理由 / 后果。
3. **过期即删或归档**：docs/ 下不允许存放"已经没用了但舍不得删"的文档——要么删，要么挪 research/ 并在本文档登记。
4. **命名**：数字前缀决定阅读顺序；新主题文档接续编号（08-xxx）。
5. **04-进度状态是唯一事实源**：组会上"做到哪了"的分歧，以它为准；它错了就当场改它。
6. 文档提交信息用 `docs:` 前缀。

## 新组员上手路径（30 分钟）

README → 01 定位 → 02 架构 → 05 环境（配好环境跑 /health）→ 03 路线图 → 认领 04 里的 ⬜ 任务。
