# ADR-0002 · 岗位数据统一接口 PostingSource

状态：生效（2026-10-26）

## 背景

招聘数据的最终来源未定：当前只能手动收集 JD 存 JSON；后续可能写爬虫脚本、接入外部数据库或招聘数据 API。不能让流水线绑死在任何一种来源上。

## 备选

a) 直接读 JSON 文件，以后换来源再重构；b) 统一接口 + 可插拔实现。

## 决定

`career_agent/datasource.py` 定义 `PostingSource` 协议（唯一方法 `fetch(keyword, limit) -> list[JobPosting]`），提供三个实现：`JsonCorpusSource`（默认，读 data/postings/*.json）、`CrawlerSource`（占位）、`ApiSource`（占位）。全局通过 `get_source()` 取实例，换数据源只改一处。

## 理由

下游（流水线①~⑤）只依赖 `list[JobPosting]` 数据结构，不依赖来源——相当于操作系统的驱动接口思路：换硬盘不改文件系统。接口成本约 30 行，换来来源自由。

## 后果

- 新数据源 = 新增一个实现类 + get_source() 切换，流水线零改动；
- 爬虫方案得以保留为占位（PPT 话术不变），何时补实现不影响主线；
- 任何实现都禁止内置 LLM 调用（数据获取与语义处理分离）。
