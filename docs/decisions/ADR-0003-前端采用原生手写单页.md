# ADR-0003：前端采用原生手写单页（路线图 M5 决策点·方案A）

- 状态：已接受（2026-10-26）
- 决策人：YiruiChen（课程项目组）

## 背景

docs/03-开发路线图 在 M5 预留了前端决策点：方案A 手写原生页面 vs 方案B PydanticAI 官方 Vercel AI / AG-UI 适配器方案。开发进入 M5 前需要确定方案才能开工。

## 备选方案

| 方案 | 内容 | 评估 |
| --- | --- | --- |
| A. 原生手写单页 | 纯 HTML/CSS/JS，SVG/Canvas 手绘图表，fetch + SSE | 零依赖零构建，完全可控，断网可演示 |
| B. Vercel AI / AG-UI 适配器 | 复用 PAI 生态现成流式 UI 组件 | 引入 npm 构建链与 React 生态，团队学习成本高，离线演示风险大 |

## 决策

采用方案A：`frontend/` 原生手写单页（index.html + app.js + style.css 可拆分），**禁止外部 CDN、禁止 npm 构建链**，图表用原生 SVG/Canvas。

## 理由

1. 演示可靠性优先（评分项"系统测试与动态改进"）：教室网络不可控，全部资源本地化 + mock 降级模式（角标标示"演示数据"）保证任何环境下页面可完整走通三块流程。
2. 课设体量匹配：页面流仅 表单→分析（条形图/映射表/时间轴）→对话面板，原生实现工作量可控，前端样式与布局的细节调整也容易做。
3. 团队协作：5 人组无需 Node 前端工程化知识即可读懂和改。

## 后果

- 放弃 Vercel AI SDK 生态的现成流式组件，SSE 打字机效果需手写（预计百行内）。
- 若后续扩展为多页/组件化应用，需引入构建工具，届时另立 ADR 取代本决策。
- 前端由后端 `server.py` 以 StaticFiles 挂载到 `/`（路由后置、存在性检查），演示时单端口单进程。
