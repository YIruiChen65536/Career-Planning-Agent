# 工作记录（logs/）

> **定位**：开发、测试、review 的过程证据，出事回溯用（"这个改动是谁、什么时候、为什么做的"），也是"系统测试与动态改进"15 分的证据链。规则见 06 手册 §8。

## 怎么写

- **每轮工作结束当天**建一篇：`YYYY-MM-DD-一句话主题.md`（同天第二轮加 `-2`）。
- **只增不改**：写错了新开一篇更正，不改旧文件。
- **篇幅 ≤ 20 行**，5 分钟写完；细节放代码和提交信息里，这里只放"何时/谁/做了什么/发现了什么"。

## 模板（复制即用）

```markdown
# YYYY-MM-DD · 一句话主题（关联里程碑/模块）

- 类型：开发 | 测试 | review（可多选）
- 谁：
- 分支/提交：

## 做了什么
-

## 测试
- 输入 / 结果：通过与否（本轮无测试则写"无"）

## Review 发现
- 谁看了什么、发现什么（本轮无 review 则写"无"）

## 遗留与下一步
- 临时文件清点：已清理 / 无产生
```
